# Ekagra — Glossary

The ubiquitous language of the life-OS model (2026-07-31 redesign session). One chain, not modules:
Identity → Goal → Plan → Commitment → Task/Occurrence → Block → Session → Entry.

- **Identity** — who Raja is becoming ("Builder", "Student"). First-class row, not a tag. Every habit must hang off one; a default "Me" identity keeps capture one-tap.
- **Goal** — a desired outcome under an Identity. Carries vision media (images). Optional for habits, required for nothing else.
- **Plan** — one node in the planning cascade: year, quarter, month, week, or day. Self-referencing (a week's parent is a month). Only the day plan is lived. Every Plan carries a canonical calendar identity: `starts_on`, the first date of its period, aligned to its horizon (year → Jan 1, quarter → Jan/Apr/Jul/Oct 1, month → the 1st, week → the ISO Monday, day → that date). One Plan per `(owner, horizon, starts_on)`; a Plan's parent is the next horizon up whose period contains `starts_on`, and only a year Plan has no parent. Today and the ISO week are therefore lookups, never searches. Upper horizons never duplicate executable rows.
- **Commitment** — the edge that places a Goal, Task, or Occurrence into a Plan. Cascading = creating commitment edges downward to the same subject, never duplicating subject rows. Horizon subject rules: a Goal may be committed to any horizon (year, quarter, month, week, day), a Task to week or day, an Occurrence to day only. So the same Goal cascades year → quarter → month → week → day as one subject, while executable subjects stay near the lived day.
- **Task** — one-shot executable work. May be committed into plans and placed into blocks.
- **HabitRule** — the durable generator for a habit: recurrence, cue link (stack anchor), minimum version, effective-date edits. Never shown as a row of work itself. Hangs off exactly one Identity (non-null; the default "Me" Identity keeps capture one-tap), and a cue link may only point at another HabitRule of the same owner and the same Identity — a Stack never crosses identities.
- **Occurrence** — one dated instance generated by a HabitRule (rolling window). Owns a one-to-one executable Task projection so Today, blocks, and Sessions keep the existing task-bound seam while rule history stays separate. `outcome` is nullable: null means pending (generated, not yet resolved), and the terminal values are done, skipped, missed. Terminal is terminal — once set, an outcome is only changed by an explicit correction, never back to pending by generation. Binary only; effort-shaped habits are Blocks + Sessions instead.
- **Stack** — an ordered cue chain of habits under an Identity (Atomic Habits habit stacking).
- **Block** — a deep, shallow, admin, or rest time-box on a day plan. A block must carry a committed task/occurrence before Focus can start from it.
- **Session** — one timer run (pomodoro), server-owned, always task-bound. Honest minutes only.
- **Entry** — journal residue on a day or session. Voice entries: transcript is the artifact (Voisu-style pipeline); audio is transient.
- **Attachment** — the one generic media mechanism (image, audio, text) on any subject. Vision boards and voice journal are both attachments.
- **Sweep** — the one-tap gesture that carries unfinished commitments forward after a broken day. Never automatic, never silent.
- **Deep hours** — honest deep-block session hours per week. The Sunday number; the metric the app owes Raja.
- **Never-miss-twice rate** — computed habit consistency (SQL view). No stored streaks, no shame mechanics.
- **Review** — the forced weekly pass over the week plan: sweep, deep hours, rates, journal playback. A projection, not a module.
